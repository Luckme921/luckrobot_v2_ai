# Jetson 控制双风扇与 ARGB 灯效手册

本文对应当前已经烧录的 **STM32F103C8T6 固件**，供后续 Jetson 程序开发和人工串口操作使用。**对用户而言，这是“一路风扇转速 + 一路灯效”的系统：两只实体风扇同步转动、同步显示灯效。**命令以 `Core/Src/main.c` 中的实现为准；硬件参数中注明了用户提供的信息与现场实测的区别。

## 1. 当前系统和已验证结果

- Jetson 通过 USB 连接 PWLINK2；PWLINK2 的 UART 与 STM32 的 USART1 相连。串口参数为 **115200 波特率、8 数据位、无校验、1 停止位（8N1）**。
- 两只风扇的原厂公母接头已将 PWM 信号互连，当前只接 STM32 **PB6**。因此 **`FAN1 n` 就是这两只风扇共同的调速命令**。虽然固件里还预留了 PB7 通道，但当前没有第二个独立控制组。
- 两只灯的 ARGB 数据线由 STM32 **PA7** 控制。实际接线下，两只灯同步响应。
- 已实测：`FAN1 100 → FAN1 20` 两只风扇明显变慢，`FAN1 20 → FAN1 50` 两只明显加快；静态红色、彩虹、呼吸与关灯均对两只灯生效。
- 上次操作结束时设置为 `FAN1 50`、`BRIGHT 20`、`COLOR 255 0 0`、`MODE STATIC`、`LIGHT ON`，并收到 `STATUS` 确认。**这些设置仅在本次运行期间有效；STM32 重启后恢复固件默认状态。**

### 最容易记住的操作模型

| 想改变什么 | 发送什么 | 两只风扇/灯会怎样 |
| --- | --- | --- |
| 风速 | `FAN1 20`、`FAN1 50`、`FAN1 100` | 两只风扇同步改变速度，灯效不变 |
| 灯的基础颜色 | `COLOR 255 0 0` 等 | 两只灯同步改变颜色；同时切回**静态**并开灯 |
| 灯的显示方式 | `MODE STATIC` / `MODE BREATH` / `MODE RAINBOW` | 两只灯同步显示固定色、呼吸或彩虹；同时开灯 |
| 亮度上限 | `BRIGHT 20` 等 | 两只灯一起调亮/调暗；不改变基础颜色或模式 |
| 灯开关 | `LIGHT OFF` / `LIGHT ON` | 两只灯一起熄灭/恢复；风扇照常转 |
| 灯珠数 | `PIXELS 64` 等 | 改变一帧数据覆盖的可寻址位置数，**不是调节风速、亮度或灯珠数量本身** |

**你喜欢的红色呼吸：**依次发送 `BRIGHT 20`、`COLOR 255 0 0`、`MODE BREATH`。先选颜色，再选模式；若最后又发送 `COLOR`，固件会回到静态色。

| 项目 | 当前资料或测量结果 | 说明 |
| --- | --- | --- |
| 风扇 | 鲲鹏 CF8 反叶正转 D 黑色，共两只 | 型号来自用户此前提供的项目总结；尚未用铭牌或厂家资料复核 |
| 单只尺寸 | 120 × 120 × 28 mm | 用户提供的商品参数 |
| 单只电机额定电压、电流 | 12 V DC、0.3 A | 用户提供的商品参数；两只额定电机电流合计约 0.6 A、功率约 7.2 W，启动电流可能更高 |
| 单只最高转速 | 2600 RPM ±10% | 用户提供的商品参数；当前未接测速线，不能实时确认 RPM |
| 电机接口 | 4 针：1 GND、2 +12 V、3 TACH/FG、4 PWM | +12 V 是电机电源；第 4 脚是控制信号，不给电机供电 |
| PWM 信号 | STM32 PB6，定时器输出 25 kHz，开漏 | 风扇第 4 脚对第 1 脚在未接控制器时曾测得约 5.1 V；STM32 只拉低或释放该线 |
| 灯光接口 | 5 V ARGB，3 针、4 个位置中一处空位 | +5 V、DATA、GND 的实际位置以接头丝印/防呆和测量为准 |
| 灯珠数量 | 商品宣称“50 多颗 RGB 灯珠” | 独立可寻址像素数及两只灯的数据级联拓扑未确认；不能据此直接推算 `PIXELS` |
| 灯光数据 | STM32 PA7，3.3 V 数据，800 kHz 兼容时序、GRB 顺序 | 当前实物已确认可显示静态红色、彩虹、呼吸；5 V 灯珠由外部电源供电 |
| ARGB 5 V 电流/功率 | 未知 | 用户尚未提供电流实测或可靠额定值，不把电机的 0.3 A 当作灯光电流 |
| 控制板 | 野火 STM32F103C8T6 最小系统板 | 固件通过 PWLINK2 烧录；板载 Micro-USB CDC 尚未确认枚举成功 |

**共地是已验证可工作接线的关键：**STM32 GND、Jetson/PWLINK2 GND、12 V 电源负极、5 V ARGB 电源负极连接到公共地。12 V 和 5 V 正极分别只给对应负载，不能接到 STM32 GPIO。之前输出无明显效果时共地尚未确认；确认共地并接至 Jetson 后功能正常，所以共地问题是最可能原因，但未做隔离故障复现实验。

当前风扇 12 V 供电为并联/原厂接头传递供电，不应将两个风扇电机串联。TACH 线尚未连接；本固件不测转速。PWM 百分比是**控制信号的高电平占空比**，不是实际 RPM 百分比；`FAN1 0` 不保证停转。

## 3. 从 Jetson 发送命令

Jetson 用户目录已放置 `~/stm32_fan_ctl.py`，项目中的对应源文件是 `jetson_serial.py`。脚本通过 `/dev/serial/by-id/usb-Arm_DAPLink_CMSIS-DAP_*-if01` 寻找 PWLINK2 串口；本次连接时它对应 `/dev/ttyACM0`。设备号可能在重插后改变，所以开发程序应优先使用稳定的 `by-id` 路径。

在 Jetson 终端输入，例如：

```bash
python3 ~/stm32_fan_ctl.py STATUS
python3 ~/stm32_fan_ctl.py 'FAN1 50'
python3 ~/stm32_fan_ctl.py 'COLOR 255 0 0'
python3 ~/stm32_fan_ctl.py 'MODE RAINBOW'
```

有空格的命令用引号包住。也可运行 `python3 ~/stm32_fan_ctl.py` 进入逐行输入模式，一行一条命令，按 Ctrl-D 退出。脚本发送 ASCII 命令和换行，读取一行回复；每次带参数调用会重新打开一次串口。Jetson 程序若直接使用 pyserial，应保持串口独占打开，按 **一条命令 + `\n` → 等一行回复** 的顺序通信，避免多个进程同时操作同一串口。固件也会在接收后约 80 ms 无新字符时处理没有换行的命令，但建议始终发送换行。

Windows 上 PWLINK2 的 UART 曾显示为 COM8；ESP32 的 COM7 不是这块 STM32 的命令口。若从 Windows 串口助手操作，选 PWLINK2 对应端口并设 115200、8N1。Jetson 当前使用的是 PWLINK2 UART，而非 STM32 板上的 Micro-USB 数据口。

### 一次恢复到已验证配置

STM32 上电或复位后，可依次执行：

```bash
python3 ~/stm32_fan_ctl.py 'FAN1 50'
python3 ~/stm32_fan_ctl.py 'PIXELS 64'
python3 ~/stm32_fan_ctl.py 'BRIGHT 20'
python3 ~/stm32_fan_ctl.py 'COLOR 255 0 0'
python3 ~/stm32_fan_ctl.py STATUS
```

`COLOR` 本身会切换到 `STATIC` 并开灯，因此这组命令无需再发 `MODE STATIC` 或 `LIGHT ON`。`PIXELS 64` 是本次测试使用的发送长度，**不是已核实的每只风扇像素数**。后续应确定级联方式与真实像素数，再调整它。

## 4. 所有可用命令

命令不区分英文字母大小写，以下使用大写以便与固件 `HELP` 对照。`n` 为十进制整数。成功时固件回复 `OK ...`；参数超范围时回复 `ERR ...`；不认识的命令回复 `ERR unknown command; send HELP`。建议以收到 `OK` 为准，不能仅以命令发送成功判断动作已执行。

### 4.1 查询与风扇

| 命令 | 参数、作用和当前接线下的效果 |
| --- | --- |
| `HELP` | 返回固件支持的全部命令概要。 |
| `STATUS` | 返回风扇通道占空比/释放状态、PWM 频率、灯的开关/模式/颜色/亮度、像素数和 DATA 引脚。它不返回实际 RPM、实测电压或灯珠电流。 |
| `FAN1 n` | **当前实际使用的唯一风速控制命令。**`n=0..100`，设置 PB6 的 25 kHz PWM；两只实体风扇同步变化。例：`FAN1 20`、`FAN1 50`、`FAN1 100`。回复 `OK FAN1`。 |
| `FAN2 n` | 固件预留命令，`n=0..100`，设置未接线的 PB7。当前执行后只会回复 `OK FAN2` 并更新状态，**不会控制任何风扇**。Jetson 上层程序无需使用。 |
| `FAN n` | 固件预留的双通道命令，`n=0..100`，同时设置 PB6 和 PB7。当前实际风速效果与 `FAN1 n` 相同，但会额外修改未用的 PB7 状态；Jetson 上层程序统一使用 `FAN1 n` 更清楚。 |
| `FAN OFF` | 释放 PB6、PB7 为不带上拉的输入，让风扇内部上拉接管 PWM 线；**不是切断 12 V 电源，也不是让风扇停止**。状态显示 `100%/FREE`，回复 `OK FAN PWM released; fan internal pull-up selects full speed`。 |

`FAN1 100` 是驱动 PWM 的 100% 占空比；`FAN OFF` 是释放 PWM 信号线。两者通常都会对应高速，但电气状态不同。控制器重启后 PB6/PB7 默认释放；风扇仍有 12 V 供电时会按自身无控制信号的行为运行。0% 下是否停转由风扇本身决定，不适合用 `FAN1 0` 当安全断电开关。上表列出 `FAN2`、`FAN` 仅为了完整记录**已烧录固件支持的所有命令**；当前使用时请只记 `FAN1`。

### 4.2 灯光颜色、亮度和像素数

| 命令 | 参数、作用和副作用 |
| --- | --- |
| `COLOR r g b` | `r/g/b` 各为 `0..255`。设置基础 RGB 颜色，**同时切换到 `STATIC` 并开灯**。例：红 `COLOR 255 0 0`、绿 `COLOR 0 255 0`、蓝 `COLOR 0 0 255`、白 `COLOR 255 255 255`、暖黄 `COLOR 255 120 0`。回复 `OK COLOR`。 |
| `BRIGHT n` | `n=0..100`，设置全局最大亮度百分比；不改变颜色、模式或开关状态。例：`BRIGHT 20`。`BRIGHT 0` 会使输出视觉上全黑，但状态仍可能是 `LIGHT=ON`；需语义上的关灯请用 `LIGHT OFF`。回复 `OK BRIGHT`。 |
| `PIXELS n` | `n=1..64`，设置 PA7 每帧发送的**可寻址像素数**。这不是灯珠电源开关，也不代表每只风扇实际灯珠总数。当前已用 `PIXELS 64` 测试两只灯的可见区域。回复 `OK PIXELS`。 |

亮度先限制在已验证的 20% 或更低，直到确认 5 V 电源、电流和接头负载。`COLOR 255 255 255` 在高亮度下可能使灯光用电较高；当前未测 5 V 灯光电流。若两只灯 DATA IN 并联，`PIXELS` 通常按每条灯串的独立像素数设置；若第一只 DATA OUT 串到第二只 DATA IN，则按两只总独立像素数设置。需要根据真实连接确认。固件上限为 64，超过上限会报错。

**“灯串珠数”到底是什么：**`PIXELS n` 指 STM32 每次沿 PA7 数据线发送多少个“可单独接收颜色的像素位置”。它不能凭空增加或减少风扇上的实体灯珠，也不是效果速度。静态红色或整串同步呼吸时，所有已收到数据的像素都是同一种颜色/亮度，所以把 `PIXELS` 从 16 改成 64，主要变化可能是**原先末端未受控的像素也收到新命令**，并不会自动出现更花哨的效果。彩虹模式会按 `PIXELS` 把色相分布在这一帧的位置上，因此数值变化可能改变彩虹在灯圈上的分布和两只灯是否显示完整。实际可寻址像素数不一定等于商品宣称的物理灯珠颗数。当前用 `64` 已看见两只灯正常工作，可先保持；以后确认数据级联与像素数再精确设置。

### 4.3 灯效模式与开关

| 命令 | 实际行为 |
| --- | --- |
| `MODE STATIC` | 显示最近一次 `COLOR` 设置的固定颜色；**同时开灯**。回复 `OK MODE STATIC`。 |
| `MODE RAINBOW` | 进入彩虹循环；**同时开灯**。彩虹颜色沿像素位置渐变并随时间移动；当前两只风扇均已实测变色。回复 `OK MODE RAINBOW`。 |
| `MODE BREATH` | 对最近一次 `COLOR` 的基础颜色做周期性明暗变化；**同时开灯**。峰值受 `BRIGHT` 限制；当前两只灯已实测同步呼吸。回复 `OK MODE BREATH`。 |
| `LIGHT OFF` | 关掉灯光输出，**保留**颜色、亮度、像素数和模式设置；风扇转速不变。当前两只灯已实测熄灭。回复 `OK LIGHT OFF`。 |
| `LIGHT ON` | 按保存的模式、颜色、亮度和像素数重新开灯；风扇转速不变。回复 `OK LIGHT ON`。 |

操作顺序很重要：`COLOR` 总会将模式改成 `STATIC`。例如要红色呼吸，先 `COLOR 255 0 0`，再 `MODE BREATH`；若顺序相反，最后的 `COLOR` 会把呼吸模式覆盖为静态。`MODE RAINBOW` 不会删除存储的 RGB 基础颜色，切回 `MODE STATIC` 时会使用那组颜色。`LIGHT OFF` 后再发 `COLOR` 或任一 `MODE` 命令会重新开灯；需要保持关闭时不要再发这些命令。

### 4.4 常用灯效组合

以下每行是发给 STM32 的**独立命令**，Jetson 脚本调用时可按上面示例逐条加引号执行。

```text
# 你喜欢的红色呼吸：红色周期性由暗变亮再变暗
BRIGHT 20
COLOR 255 0 0
MODE BREATH

# 20% 静态红色
BRIGHT 20
COLOR 255 0 0

# 20% 静态蓝色
BRIGHT 20
COLOR 0 0 255

# 10% 暖黄色呼吸
BRIGHT 10
COLOR 255 120 0
MODE BREATH

# 15% 蓝色呼吸：颜色较柔和
BRIGHT 15
COLOR 0 40 255
MODE BREATH

# 15% 紫色静态
BRIGHT 15
COLOR 150 0 255

# 10% 青色静态
BRIGHT 10
COLOR 0 180 180

# 20% 彩虹循环
BRIGHT 20
MODE RAINBOW

# 暂时熄灯，随后恢复之前的效果
LIGHT OFF
LIGHT ON

# 彩虹后回到上次设置的固定颜色
MODE STATIC
```

上面的 `#` 是手册注释，**不要作为串口命令发送**。如需直接粘贴到 Jetson 的逐行输入模式，只输入非注释的命令行。

目前固件只有 **静态、彩虹、呼吸** 这三种模式，没有“流水”“闪电”“温控自动变色”等命令。红色呼吸和彩虹都已在两只实体风扇上实测；其余 RGB 组合由相同颜色/模式命令构成，可按喜好调整，但尚未逐一实物观看。

## 5. 固件上电默认状态与回复解释

根据当前固件源码，STM32 每次复位后的默认值为：`FAN1=100%/FREE`、`FAN2=100%/FREE`（PB6/PB7 释放），`LIGHT=OFF`、`MODE=STATIC`、基础颜色 `RGB=8,8,8`、`BRIGHT=8`、`PIXELS=16`。这些不是持久配置；Jetson 后续若要自动恢复目标转速/灯效，需要在连接 STM32 后重新发送初始化命令。

已验证的运行时状态查询结果形如：

```text
FAN1=50% FAN2=100%/FREE PWM=25kHz PB6/PB7 OD; LIGHT=ON MODE=STATIC RGB=255,0,0 BRIGHT=20 PIXELS=64 DATA=PA7
```

这里 `FAN2=100%/FREE` 表示 PB7 未被 PWM 驱动；**并不表示第二只物理风扇在 100% 转速**。目前两只物理风扇都受 PB6 的 `FAN1=50%` 控制。`STATUS` 报告的是固件目标设置，并非风扇测速读数或灯光实际电流。

## 6. 给后续 Jetson 程序的接口约定

1. 串口发现：优先匹配 `/dev/serial/by-id/usb-Arm_DAPLink_CMSIS-DAP_*-if01`；本次实例为 `/dev/ttyACM0`。如果找不到或匹配多个，不应随意选其他设备。
2. 串口配置：115200、8N1；每条命令使用 ASCII，末尾加 `\n`，等待一行以 `\r\n` 结束的回复；一次只保留一个读写客户端。
3. 上电初始化：发送 `FAN1 50`、`PIXELS 64`、`BRIGHT 20`、`COLOR 255 0 0`，逐条确认 `OK`，再读 `STATUS`。这是当前实物验证过的起点；实际像素数确认后应修改 `PIXELS`。
4. API 语义：把风扇控制作为 **PB6 上的共同占空比**；灯光保留 `mode`、`rgb`、`brightness`、`pixels`、`enabled` 五种状态。因为 `COLOR`、`MODE` 会开灯且 `COLOR` 会切静态，Jetson 上层逻辑应按最终期望状态安排命令顺序。
5. 故障判断：仅收到 `OK` 表示 STM32 解析并更新了设置，不证明物理转速或灯光一定变化。检查 `STATUS`、共地、12 V/5 V 供电、PA7/PB6 接线；当前没有 TACH/RPM 反馈或电流监测。
6. 通信异常：若无回复，先确认 PWLINK2 UART RX→STM32 PA9、PWLINK2 UART TX→STM32 PA10，以及公共 GND、115200 波特率和串口是否被其他进程占用。不要把 PWLINK2 的 SWD TCK/TMS 当成 UART 数据线。

## 7. 后续改用 USB 转 TTL 串口模块

PWLINK2 目前同时承担烧录器和 USB 转串口功能。以后可以单独使用 USB 转 TTL 模块替代它的**串口通信功能**，不必为更换串口模块修改 STM32 命令固件。普通 USB 转 TTL 模块不能替代 PWLINK2 的 SWD 烧录/调试功能。

接线时先断电：模块 **TXD → STM32 PA10（RX）**，模块 **RXD ← STM32 PA9（TX）**，模块 **GND ↔ STM32 GND**；Jetson 插模块的 USB 端。UART 信号必须是 **3.3 V TTL 电平**。只用 USB 给模块自身供电时，模块的 `5V`、`VCC` 输出脚不要接 STM32 或风扇电源；如果模块有电平选择开关，确认它切换的是 **TX/RX 信号电平**，而不只是 VCC 输出电压。可在未连接 STM32 时用万用表量模块 TXD 空闲高电平，确认约 3.3 V 后再接线。STM32、模块、风扇电源仍需公共 GND。

对截图中的商品选项，优先选**明确标注 TXD/RXD 为 3.3 V、带 GND、适用于 Linux 的 CP2102 或 CH340G 模块**；当前 ESP32 板已使用 CP2102，PWLINK2 也已证明 Jetson 可通过 USB 串口通信。如果偏好线状外形，可以选满足同样条件的线状模块，但不能仅凭“USB 转 TTL”或照片判断 TXD 是否为 3.3 V。截图里标为 **PL2303HX** 与 **PL2303TA** 的版本属于较老系列；厂商已将 TA/HXD 等列为停产，不作为新购首选。若已经买了 PL2303 线，先确认具体芯片版本、Linux 枚举及 TXD 空闲电压，再决定是否接 STM32。切换模块后，Jetson 设备路径和现有脚本的 PWLINK2 专用匹配规则也要更新。

芯片厂商资料：[Silicon Labs CP210x VCP 驱动](https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers)、[沁恒 CH340 产品与 Linux 驱动](https://www.wch.cn/products/CH340.html)、[Prolific PL2303 系列与停产标注](https://www.prolific.com.tw/en/products/smart-i-o-solution-en/usb-1-1-to-uart-serial-printer/)。这些资料只能确认芯片系列的驱动/规格；**具体商品小板或线材的 TTL 电平仍需看卖家电路并实际测量**。
